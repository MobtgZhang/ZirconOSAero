# 问题 #21：文件后备 CoW 旧帧未释放

## 1. 问题编号

`21`

## 2. 问题位置

- 文件路径：`src/mm/vm.zig`
- 函数/模块：`tryCowWriteFault`
- 行号或代码片段：原实现只释放新帧的错误路径，未释放重映射后不再使用的旧帧。

## 3. 问题描述

当文件后备页 `shareCount == 0` 时，旧物理帧只属于当前进程；重映射到新帧后旧帧被泄漏。

## 4. 复现路径

映射文件后备只读页并写入，触发 CoW；观察旧物理帧是否仍被占用。

## 5. 影响范围

造成文件后备私有化路径的物理帧泄漏，长期执行可耗尽内存。

## 6. 严重程度

High

## 7. 可能原因

CoW 成功路径缺少对无共享旧帧的释放。

## 8. 权威参考依据

- Windows NT/ReactOS 内存管理语义：私有帧重映射后旧帧若无其他引用应释放。
- 本次修复来自源码审计与测试，未将 REA 二进制分析结论作为修复依据。

## 9. 建议修复方案

已在 `remapLeafPhysical()` 成功后，对 `old_share_count == 0` 的旧帧调用 `free(old_phys)`；共享路径继续仅释放共享计数。

## 10. 验证方法

通过现有 CoW 测试验证映射切换正确；后续可增加帧位图断言验证旧帧回收。
