# 问题 #10：堆块前向合并时丢失尾部空闲块

## 1. 问题编号

`10`

## 2. 问题位置

- 文件路径：`src/mm/heap.zig`
- 函数/模块：`insertFreeBlock()`
- 行号或代码片段：原实现在 `prev` 合并时直接执行 `pr.next = block.next`，未保证链头在结果为最后一个节点时仍指向合并后的块。

## 3. 问题描述

`insertFreeBlock()` 同时处理前向合并、后向合并和按地址插入。当释放块 `block` 同时与前一个块 `prev` 和后一个块 `cur` 相邻时，代码先把 `cur` 合并进 `block`，再把 `block` 合并进 `prev`。合并后 `prev.next` 会被写成 `block.next`；若 `block` 是空闲链表最后一个节点，则 `block.next` 为 `null`，空闲链头也会被写成 `null`，导致已合并的尾部块从链表中消失。

## 4. 复现路径

在堆中分配三个地址连续的块 `a`、`b`、`c`，按 `b`、`a`、`c` 的顺序释放。释放 `b` 后形成中间块；释放 `a` 时中间块先合并入 `a`；释放 `c` 时触发前向、后向双重合并。此场景可用单元测试稳定复现，修复前 `freeListDebug().nodes` 会变为 0，修复后应为 1。

## 5. 影响范围

- 永久丢失部分空闲堆区间，降低堆可用容量。
- 后续分配可能在仍能推进的高水位中意外失败。
- `heap_check()` 与空闲链表调试统计可能无法覆盖实际物理空闲区域。
- 影响使用内核堆的池、对象、驱动与文件系统路径的长期稳定性。

## 6. 严重程度

- High

## 7. 可能原因

合并逻辑只更新了相邻节点的 `next` 指针，没有区分“被合并块是链尾”的特殊情况，也没有在所有合并结果上重新校验链头。

## 8. 权威参考依据

- 项目源码 `src/mm/heap.zig` 的 `insertFreeBlock()`、`freeListDebug()` 与堆单元测试。
- 通用空闲链表与相邻块合并行为依据操作系统内存管理教科书语义；本问题属于实现内部不变量错误，不需要引用 Windows 7 专有源码。
- `/home/mobtgzhang/api.json` 是 REA 接入配置，不是堆内部实现文档；本报告未声称存在该文件中的堆 API 描述。
- 本报告未使用 REA 结论，因为 Windows 内核堆的内部空闲链布局不属于本实现需要一比一观察复刻的公共行为。

## 9. 建议修复方案

`prev` 合并后仍保留 `prev` 作为新的合并块地址，并在 `block.next == null` 时显式将 `free_head` 设回 `prev`。该修复只恢复空闲链表完整性，不改变分配对齐、头部开销或可观察的 Windows 7 池语义。

## 10. 验证方法

- 新增单元测试 `heap coalesces adjacent block behind prev merge`：连续分配三块，按中间、前、后顺序释放，断言空闲链表只剩一个节点。
- 运行 `zig build test` 与 `zig build -Darch=x86_64`。
- 后续可继续使用现有 `heap random alloc free stress` 压力测试回归。
