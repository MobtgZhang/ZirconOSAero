# 问题 #29：对象命名空间重复插入、超长截断与删除后容量泄漏

## 1. 问题编号

`29`

## 2. 问题位置

- 文件路径：`src/ob/object.zig`
- 函数/模块：`initNamespace`、`lookupNamespace`、`insertNamespace`、`insertSymbolicLink`、`removeNamespace`
- 行号或代码片段：原实现只使用 `namespace_count` 顺序追加；插入不查重且截断超长名称，删除清空条目但不释放槽位。

## 3. 问题描述

同名条目可重复插入，删除只移除首个匹配且留下永久占位；超过 64 字节的名称被静默截断，可能形成错误匹配。重复初始化还会再次追加默认目录。

## 4. 复现路径

对同一名称多次调用 `insertNamespace` 或 `insertSymbolicLink`；插入 65 字节名称后查询截断名；删除条目后重复插入 1024 次触发容量耗尽。

## 5. 影响范围

影响命名对象、符号链接、设备目录和命名打开路径。可造成名称解析到错误对象、容量耗尽、删除后残留同名条目以及初始化重入行为不确定。

## 6. 严重程度

Medium

## 7. 可能原因

命名空间使用顺序追加但删除不清理占用状态，且插入前缺少完整验证和唯一性检查。

## 8. 权威参考依据

- Windows NT 对象命名空间中的目录项名称在其所属目录内具有唯一性，删除目录项应移除对应名称解析。该依据来自公开 NT 对象命名空间语义。
- 本次修复来自源码审计，未将 REA 二进制分析结论作为修复依据；未执行 `ntoskrnl.exe` 对应函数级对照。

## 9. 建议修复方案

已引入 `namespace_used` 槽位表和命名空间 IRQ 自旋锁。插入前拒绝空名、超长名和重复名；删除时标记槽位空闲并递减活跃数量；插入时复用空闲槽位；`initNamespace` 会清空全部槽位，避免重入重复注册。符号链接名称和目标在同一个锁保护区间内写入。

## 10. 验证方法

新增宿主测试验证同名插入失败、删除后活跃数量还原、空闲槽位可复用以及重初始化不累积重复目录。后续可结合命名打开 API 测试符号链接解析和并发插入删除。
